# 0013. チャンネル作成をBotコマンド経由での代理作成に変更する

## ステータス

決定（Accepted）。[0012](./0012_private_channel_protection.md)の決定を撤回する。

## コンテキスト

[ADR 0012](./0012_private_channel_protection.md)では、一般ユーザーにチャンネル作成を許可する手段として、Discordのロールへ`Manage Channels`権限を付与する運用を採用し、その副作用（ロール保持者が他人の非公開チャンネルまで操作できてしまう問題）をBotが新規チャンネル作成イベントを監視して都度保護する方式で解決していた。

この方式には、運用面・セキュリティ面の双方で無視できない問題があることが実運用の検証で判明した。

- `Manage Channels`はチャンネル単位ではなくギルド全体に及ぶ権限であり、チャンネルを作成できるようにしたい既存ロールが複数ある場合、それぞれのロールに個別に権限を付与する必要があり煩雑（対象ロールをチャンネル作成専用の1ロールに集約する運用でも回避できるが、それでも次の問題は残る）
- チャンネル単位のオーバーライドでロールから`View Channel`/`Manage Channels`を剥奪しても、対象チャンネルが属する**カテゴリ**側の権限設定で当該ロールに`View Channel`が許可されており、かつ「権限をカテゴリと同期」が実行されると、Bot側が設定した個別チャンネルのDenyがカテゴリ側の設定で丸ごと上書きされてしまう。この経路はチャンネル単位の保護では原理的に塞ぎきれない
- 上記に加え、Botの招待権限に`Administrator`が必要になる（一般ユーザーが作成した直後の非公開チャンネルをBot自身がまだ閲覧できないため、常にオーバーライドをバイパスできるAdministrator権限がないと保護のための権限変更自体が実行できない）。Botが乗っ取られた場合の影響範囲が大きい

これらの問題は、一般ユーザーへ`Manage Channels`という強力かつギルド全体に及ぶ権限を付与すること自体に起因する構造的な問題であり、チャンネル単位の後追い保護では解消できない。

## 決定

一般ユーザーへのDiscordロールへの権限付与はやめ、チャンネル作成はBotコマンド経由でBot自身の権限を使って代理作成する方式に変更する。

- `@Bot channel create <チャンネル名>` というメッセージコマンドを新設し、`internal/interface/discordbot/channel_handler.go`が受け付ける
- チャンネル名は`internal/domain/channel.Name`で検証する（半角英小文字・数字・ハイフン・アンダースコアのみ、最大100文字。※日本語（ひらがな・カタカナ・漢字）は後日許可された。現在の許容文字集合は実装を参照）
- 作成されるチャンネルは常に公開のテキストチャンネルで、カテゴリ指定は行わない（`@everyone`の閲覧権限を含むギルドのデフォルト権限をそのまま継承する）。非公開チャンネルの作成はこのコマンドではサポートしない
- Bot自身に必要な権限は`Manage Channels`のみで足りる。`Administrator`は不要になる
- 一般ユーザーへロール経由で`Manage Channels`権限を付与する運用は行わない

[0012](./0012_private_channel_protection.md)で導入した`ChannelCreate`イベント監視によるロール保護機構（`internal/domain/channel.IsChannelManagerRole`/`IsPrivate`、`internal/infrastructure/discord/channel_restrictor.go`、`internal/interface/discordbot/channel_handler.go`のイベントハンドラ部分）は全て削除する。

なお、チャンネル作成の乱立を防ぐための承認フロー（提案とリアクションによる可決）は別途[ADR 0014](./0014_channel_creation_approval_voting.md)で扱う。

## 影響

- Botの招待権限が`Manage Channels`のみで済むようになり、権限が乗っ取られた場合の影響範囲が縮小する
- サーバー管理者はDiscordのロール設定を一切操作する必要がなくなる。Botコマンドを使えるメンバーであれば誰でもチャンネル作成を提案できる（提案の可決条件は0014参照）
- カテゴリ権限同期によるチャンネル単位保護の迂回リスクは、保護機構自体を廃止したことで構造的に解消される
- チャンネル作成コマンドを使えるかどうかを特定のロールだけに制限したい場合、Bot側のコマンド権限チェックとして別途実装する必要がある（本ADR時点では未実装。Botにメンションできる全員が提案可能）
