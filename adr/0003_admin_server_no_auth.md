# 0003. 管理Webサイトは認証なし・ネットワーク到達性の制限のみで公開範囲を制御する

## ステータス

決定（Accepted）

## コンテキスト

`internal/interface/admin` の管理Webサイト（キーワード追加/削除、通知チャンネル設定）にはログイン等の認証機構がない。初期実装のコードレビューで、この画面が無防備に公開され得る点が指摘された。

現在の設計は以下の2点で到達性を制限している。

- `docker-compose.yml` でホスト側のポートを `127.0.0.1:${ADMIN_PORT:-8080}:8080` として、ホストのループバックアドレスにのみ公開する
- `cmd/bot/main.go` の `http.Server` はコンテナ内部で `:8080`（全interface）にbindする。これはDockerのポートマッピングがコンテナの `0.0.0.0` 宛てトラフィックを転送する仕組みのため、コンテナ内部で `127.0.0.1` に固定するとDocker経由のアクセス自体が機能しなくなり不可能

## 決定

管理Webサイトには認証機構を追加せず、ネットワーク到達性の制限（Docker運用時はホスト側127.0.0.1限定公開）のみで公開範囲を制御する運用を継続する。

- `cmd/bot/main.go` の `http.Server.Addr` は `":" + cfg.AdminPort` のまま維持し、bind先はコメントで意図を明記する
- Docker以外の環境（直接 `go run`/バイナリ実行等）で起動する場合は、呼び出し側の責任でファイアウォール等によりネットワーク到達性を制限すること

## 影響

- Docker経由でない直接実行時は、`ADMIN_PORT` が全ネットワークインターフェースに公開される。README・`.env.example` にこの前提を明記し、直接実行を行う場合は利用者自身がアクセス制御を行う必要がある
- POSTフォームによる操作（キーワード追加等）にはCSRFトークンもないため、ネットワーク到達性の制限が破られた場合はCSRFのリスクもある
- 将来的に外部公開が必要になった場合は、本ADRを新しいADRで上書きし、認証機構（Basic認証やセッションベース認証など）を追加すること
