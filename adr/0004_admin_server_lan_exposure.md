# 0004. 管理Webサイトのポート公開範囲をLAN内に拡張する

## ステータス

決定（Accepted）

## コンテキスト

[0003](./0003_admin_server_no_auth.md) では管理Webサイト（`internal/interface/admin`）を `docker-compose.yml` でホスト側の `127.0.0.1` にのみバインドし、Dockerホスト機自身からのみアクセス可能な状態にしていた。

運用上、Botを動かしているDockerホストとは別の端末（同一LAN内のPC・スマートフォン等）からも管理画面を操作したいという要望があり、`127.0.0.1` 限定公開ではLAN内の他端末から到達できず不便であった。

## 決定

`docker-compose.yml` のポートマッピングを `127.0.0.1:${ADMIN_PORT:-8080}:8080` から `${ADMIN_PORT:-8080}:8080` に変更し、ホストの全ネットワークインターフェースへ公開する。これにより同一LAN内の他端末から `http://<ホストのIP>:8080` でアクセスできる。

- `cmd/bot/main.go` の `http.Server` は既にコンテナ内部で全interfaceにbindしているため変更なし
- 管理Webサイトには引き続き認証機構を追加しない（[0003](./0003_admin_server_no_auth.md)の決定を維持）。到達性の制限範囲を「Dockerホスト機のみ」から「同一LAN内」に広げる決定のみ

## 影響

- 同一LAN内であれば誰でも管理画面（キーワード追加/削除、通知先チャンネル設定）を操作できるようになる。信頼できないデバイスが同じLANに存在する環境（公衆Wi-Fi相当のネットワーク等）では利用しないこと
- インターネットへの到達性は本変更では変えていない。ルーターのポート開放（NAT越え）等を別途行わない限りインターネットからは到達できないが、利用者側でルーター設定を変更しないよう注意が必要
- POSTフォームにCSRFトークンがない点は[0003](./0003_admin_server_no_auth.md)から変わらずリスクとして残る。公開範囲の拡大によりCSRFの攻撃面（同一LAN内の悪意ある端末やスクリプトから）がやや広がる
- 将来的に不特定多数がアクセス可能なネットワークでの運用が必要になった場合は、本ADRを新しいADRで上書きし、認証機構の追加を検討すること
